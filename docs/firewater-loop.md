# Wade / Ember 행동 루프

두 프로필은 `prompts/firewater.conversing.md`를 공유한다. 역할·위험물·출구·파트너 이름은 서버의 현재 스테이지 정보로 채운다.

자율 플레이는 `현재 관찰 → 한 가지 행동 결정 → 실행 결과 저장 → 빠른 재관찰`을 반복한다. `FirewaterLoop`는 현재 목표·장치·발판 점유자, 마지막 행동 결과, 실패한 접근, 통로 작업 단계와 진행 정체를 보존한다. 이 상태는 이전 대화 요약보다 우선하며, 게임 중 기억 압축에는 별도 모델을 호출하지 않는다. 구체적인 사람 요청은 자율 루프를 잠시 멈추고 최대 여섯 번의 명령으로 처리하며, 매 판단 전에 자율 루프와 동일한 관찰 준비 단계를 거친다. `clear this game`, `do your To-do`, `게임 계속해` 같은 명시적 재개 요청은 이 짧은 처리 루프를 거치지 않고 스테이지 목표를 재개한다. 요청에 따른 도착·대기는 명시적인 재개 요청까지 유지한다.

- `!observeFirewater`: 렌더링/모델 호출 없이 16블록 내 시야로 검증한 목표, 장치 전원, 발판 점유자, 사다리, 변화 정보를 반환한다.
- `!inspectFirewater`: 경로나 높이가 불분명할 때만 네 방향 이미지를 분석하고, 통로가 보이면 그 상단·착지 지점을 향한 다섯 번째 화면을 추가한다. 분석이 끝난 뒤 현재 월드를 다시 확인하여 좌표 권한을 발급한다. 모델 대기는 최대 45초이며, 중단되거나 이전 스테이지에 속한 응답은 행동에 사용하지 않는다. 중단·스테이지 변경·시간 초과는 Codex 전송까지 취소한다. Codex 이미지 요청 자체의 제한은 30초다.
- `!traverseFirewater(x,y,z)`: 관찰한 사다리·통로를 지정한다. 사다리의 착지점 또는 열린 벽 너머의 목적지를 계산한다. 통로 표식이 공중에 있으면 연결된 공기 아래의 실제 발 높이를 찾고, 입구를 거쳐 통로 너머로 이동한 뒤 도착을 검증한다. 자율 이동에는 역할별 경로 제한을 적용한다. 사람의 발판 유지 정보와 작업 단계를 함께 기억하며, 도착 후 짧게 알린다.
- `!exploreFirewater(8)`: 정보가 없을 때만 다른 관측점을 찾는다. 발견한 목표에는 최소 거리 필터를 적용하지 않으며, 가까운 사다리는 직접 통과하도록 안내한다. 새 좌표에 도착했다는 사실만으로 퍼즐 진행을 인정하지 않는다.
- 같은 장소의 유효한 관찰과 같은 장면의 이미지 분석은 반복하지 않는다. 두 번 탐색해도 목표·장치·통로 정보가 늘지 않으면 다른 행동이나 협력을 요청한다. 진행 없이 차단된 명령을 세 번 요청하면 장애물을 한 번 알리고, 환경 변화나 상대 지시를 기다린다.
- 좌표 권한은 30초 유지한다. 승인된 이동 도중의 만료 때문에 처음부터 다시 관찰하지 않으며, 도착 후 현재 블록·역할·범위·시야/정확한 발 위치·스테이지를 재검증한다.
- 성공한 상호작용은 좌표 권한만 무효화한다. 발견한 목표는 기억하며, RESET/새 START에서 스테이지 기억을 비운다.
- 실패한 동일 접근은 이동 위치나 실제 통로가 바뀌기 전까지 반복하지 않는다. 단순 발판 전원 변화는 실패 기억을 지우지 않는다.
- 발판/출구 도착 시 유지 상태를 기록해 자율 이동을 막는다. 의존 작업 완료나 계획 변경이 확인되면 `!releaseFirewaterHold`로 해제한다. 유지 중에는 상태 변화나 상대 메시지가 있어야 다시 판단한다.
- 협력 요청에는 탐색 횟수 조건이 없다. 봇 대화는 네 메시지 이내이며 사람에게는 일반 채팅을 사용한다. 대화 종료는 사람의 대기 지시를 해제하지 않는다.
- 기존 자동 탈출 모드는 Firewater에서 실행하지 않는다. 이동 명령은 45초 후 중단을 요청한다. 안전 이동·역할·장치 권한 검사는 계속 적용된다.

검증: `npm run test:firewater`, `npm run lint:firewater`.
실제 서버에서의 자율 클리어, 이미지 모델 품질과 동적 사다리 주행은 별도의 플레이 검증 대상이다.

## 응답 시간과 추론 제어 (2026-10-12)

- Wade와 Ember의 대화·이미지 모델은 `gpt-6.1-sol`, `reasoning.effort=low`, `text.verbosity=low`를 명시한다. 공식 API 문서의 기본값은 medium이며 none/minimal은 지원하지 않는다. 로컬 Codex UI 기본값과 API 기본값을 혼동하지 않는다.
- 한 번에 현재 증거가 뒷받침하는 안전한 다음 행동만 결정한다. 전제 조건이 충족되면 실행하고 결과로 재판단한다. 새 반증 없이 결정을 반복 검토하지 않으며, 증거가 없으면 표적 관찰 또는 구체적인 질문 하나로 전환한다. 역할·위험물·좌표 검증과 인간의 대기 지시는 그대로 우선한다.
- 고정 규칙과 명령 문서를 프롬프트 앞에 두고, 자주 변하는 목표·기억·관찰은 뒤에 둔다. 안정적인 접두부를 재사용할 수 있게 하되 캐시 적중을 보장하지는 않는다.
- 프로필의 요청 간 cooldown은 0이며 자율 행동 완료 뒤에는 150ms만 양보한다. 실패/대기 상태의 5초 재시도 간격은 유지하여 바쁜 반복을 피한다.
- Codex 대화 요청은 20초, 이미지 요청은 30초에 전송 자체를 취소한다. 시간 제한은 추론을 성공적으로 끝내는 기법이 아니라 대기 상한이다. Firewater의 한 판단 안에서 실패 요청을 세 번 연속 재시도하지 않는다.
- SSE는 `response.completed`에서 완성된 응답을 반환하고 리더를 닫는다. 소켓 종료까지 추가로 기다리지 않으며, 부분 명령·실패·incomplete·완료 전 연결 끊김은 행동 결과로 반환하지 않는다. 토큰 조각 단계에서 명령을 실행하지 않는다.
- `[decision-observation]`은 관찰 시간, `[decision-preparation]`은 cooldown과 프롬프트 준비 시간을 기록한다. `[codex-request]` / `[codex-response]`는 요청별 HTTP 헤더·첫 이벤트·첫 출력·완료 시간과 input/cached/output/reasoning token 수를 기록한다. 토큰 값은 서버가 제공한 경우에만 기록하며, 첫 출력 전 시간 전체를 추론 시간으로 간주하지 않는다. 인증 정보·원문 프롬프트·숨겨진 사고 내용은 이 계측 로그에 남기지 않는다.
- 모델 자동 탐색에서 `.test.js`를 제외한다. 봇을 시작할 때 mock 모델 테스트와 fallback 로그가 실행되는 문제를 막는다.

근거: [Sol 6.1 모델 설정](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [추론 프롬프트 권장사항](https://developers.openai.com/api/docs/guides/reasoning-best-practices), [응답 지연 최적화](https://developers.openai.com/api/docs/guides/latency-optimization). 공식 문서의 간단하고 직접적인 지시, 낮은 추론 강도, 짧은 출력, 불필요한 요청 축소 원칙을 적용했다. 짧은 출력 지시만으로 내부 추론을 제한할 수 있다고 가정하지 않는다.

검증: 새 물·용암·독 블록이 나타난 뒤 다음 판단으로 이어지는 Wade/Ember × 자동/사람 요청 통합 테스트, SSE 완료/끊김/불완전 응답/UTF-8 분할/취소/시간 제한/계측 테스트를 포함해 전체 129개 통과. 실제 Codex에서 간단한 안전한 보석 선택은 low 설정으로 2.98초, 보고된 reasoning token 0이었다. 단일 기능 검증이므로 기존 설정 대비 성능 향상률이나 전체 퍼즐 클리어 품질을 입증하지는 않는다.

## 사람의 직접 지시 (2026-10-12)

사람의 구체적인 요청을 처리하는 동안에는 게임 내 위험을 사용자가 선택한다. 물·용암·독, 역할별 장치/보석 제한, 스테이지 경계, 기존 발판 유지와 실패 이력 때문에 요청한 이동·상호작용을 거부하지 않는다. 사람에게만 `!goToCoordinates`를 노출하며, 요청된 좌표의 관찰 유효기간/시야를 안전 승인 조건으로 요구하지 않는다. 실제로 로드된 블록인지, 조작 가능한 종류인지, 물리적으로 이동했는지와 서버가 수집을 확인했는지는 계속 확인한다. 이동을 위해 지형을 자동으로 파괴하거나 발판을 설치하지 않는다.

예외는 AsyncLocalStorage로 해당 사람 요청·봇·스테이지 세대에만 묶인다. 요청 종료/실패/RESET 이후에는 자율 행동에 전파되지 않는다. 질문만 한 경우에는 발판 유지를 해제하지 않고, 요청을 실행하는 이동 명령이 나왔을 때 기존 유지를 해제한다. 명시적인 게임 재개 요청은 자율 안전 규칙으로 돌아간다.

사람이 사다리 등반을 요청하면 상단의 안전한 바닥을 찾는 것을 선행 조건으로 삼지 않는다. 사다리 부착면을 향해 전진·점프 입력을 보내며 실제 높이 변화로 등반을 확인한다. 3초 동안 수직 진행이 없거나 30초를 넘기면 물리적인 실패를 보고하고 입력을 정리한다. 가까운 사다리 위층에서 사람이 부르면 같은 등반 경로를 사용한 뒤 사람에게 접근한다. 상단에 올랐다는 사실만으로 통로 통과나 퍼즐 완료를 선언하지 않는다.

Wade와 Ember에 공통 적용한다. 실제 서버의 사다리 충돌/등반 물리는 별도의 플레이 검증 대상이다.


## 열린 통로의 바닥 좌표 (2026-10-12)

문이 열릴 때 같은 x/z 열의 공기 좌표는 가장 낮은 높이를 보존한다. 인접한 통로 열은 합치지 않는다. 관찰과 이동은 표식에서 아래로 이어진 공기를 따라 로드된 바닥과 머리 공간을 찾으며, 고체 바닥을 관통해 다른 층을 선택하지 않는다.

통로 이동은 보정한 입구에 먼저 도착한 뒤 벽틀 방향과 실제 지형으로 계산한 반대편 목적지로 이동한다. 위로 한 칸, 아래로 세 칸까지의 단차를 후보에 반영하고 실제 이동 가능 여부는 경로 탐색으로 확인한다. 사람의 직접 지시에는 기존 게임 위험 제한 해제를 유지한다. 바닥 계산 실패, 경로 없음, 이동 실패, 도착 미확인을 구분하며, 계산 실패만으로 통로가 닫혔거나 위험하다고 보고하지 않는다. RESET이나 통로 폐쇄 뒤에는 성공으로 기록하지 않는다.

검증: 전체 149개 테스트와 Firewater lint 통과. 실제 경로 탐색기를 사용해 Wade/Ember × 자율/사람 지시, 공중 표식, 단차, 옆에서의 접근, 통로 폐쇄와 RESET을 확인했다. 서버에서의 실제 통과 여부는 별도의 플레이 검증 대상이다.
